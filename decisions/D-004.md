User clarification, 2026-09-24: the UI must not suggest that every branch owns a
different Command Center. Show one central plan plus all local worktree activity
at once. Task branches carry progress updates and code; their states retain
provenance and become accepted through ordinary integration.

Subsequent user decision: use an orphan command branch containing only .command.
Do not create a sibling planning directory. Read and write the branch directly
with Git plumbing; document plain-Git CRUD. MCP is optional convenience within
Command Center, sharing its writer with the UI and CLI. One shared project plan
links tasks to code branches/commits and shows every worktree together.

This supersedes the earlier assumption that each source checkout carries planning
files. Existing history is preserved. No main/master rename is required. Code and
planning commits are separate; concurrent planning writes use expected revisions
and Git ref compare-and-swap. There is no new agent runner or mandatory service.
